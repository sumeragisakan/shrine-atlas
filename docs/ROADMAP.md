# 工作目标与路线图

更新：2026-10-30。阅读本文件前先看 [项目交接](CODEX_HANDOFF.md)。下列勾选框均为未完成工作，除“当前已完成”一节外不代表已有实现。

## 研究方向与优先顺序

用户希望研究不同神祇的奉祀分布、集中区域与重叠，并长期扩展为可结合三维地形及简单 AI 神社模型的本地项目。

| 阶段 | 状态 | 用户方向与边界 |
| --- | --- | --- |
| 现有二维目录与首轮全国资料 | 已完成首轮 | 继续保持可用；不是现况、文献及定位全部完成 |
| M1 神祇热度对比 | 下一项功能，尚未实现 | 最多三位神祇，以不同颜色同时显示密度并观察重叠 |
| M2 定位补全与复核 | 已记录，留待未来推进 | 独立数据工程，不作为本次交接或 M1 原型的前置全量任务 |
| M3 三维地形 | 未来探索 | 尚未选择引擎、地形来源、分发方式和性能预算 |
| M4 简单 AI 神社模型 | 未来探索 | 尚无资产、生成工具或确定工作流；不声称真实建筑已还原 |

M1 可使用现有坐标做诚实展示；M2 补点后更新索引。M3、M4 先做一个地点的小样，不要求先把全国迁移到三维框架。

## M1：最多三位神祇的热度对比

### 用户明确要求

- [ ] 增加神祇筛选，研究祭祀该神祇的神社分布密度。
- [ ] 最多同时选择三位神祇，各有不同颜色，叠加观察分布与重合。

### 已讨论的设计方向

- [ ] 与现有目录浏览并列的比较模式；搜索添加神祇，每层独立显示、隐藏、移除，固定颜色与清晰图例。
- [ ] 三层共用平滑半径和绝对密度刻度，半径用可解释的地理距离。相对分布模式可后续增加，和绝对密度明确区分。
- [ ] 图例显示每位神祇的匹配记录数、已定位记录数及定位覆盖率；口径随来源、地域和角色筛选一致变化。
- [ ] 无资料或定位覆盖不足的地区标明数据不足，热图的零值与未知状态可区分。
- [ ] 可区分来源明确标注的主祭、配祀、合祀及未区分角色；历史材料可单独控制。
- [ ] 保留原文神名，通过可核对的异写／别名对应来比较；争议神格关系允许分开观察。
- [ ] 保留点击神社查看原始名单和逐项出处的路径，能从热图追溯到本次参与计算的记录。

这些方向不表示已选定算法、图形库或全部统计参数；开发时把采用的默认值写进方法说明。

### 数据口径与工程建议

1. **先做祭神提及→可比较神格的对应层。** 现有 `kami[].names` 不是规范神格表，有时一个原文项目含多位神祇。建议单列神格 ID、提及位置、解析结果、对应理由、证据及审查状态；不覆写原始 `kami`。本文件不指定新的文件名或声称这些表已经存在。
2. **来源筛选到祭神组。** `agency` 记录可能仅由历史表提供某位神祇。默认优先机构明确记载、历史组单独控制是建议口径；实现时在图例公开，不把机构网页访问日期当作祭祀现况日期。未能确定角色的项目只进入“全部／未区分”，不能猜主祭。
3. **避免重复放大。** 同一记录 ID 对同一神祇只计算一次，不能因多个异写、来源或祭神组反复增加权重。可能重复的历史／机构实体尚未完全消解，因此首先称“来源记录密度”，并披露可能重复的限制。
4. **多地点另定规则。** 一条记录可能有本社与奥宫。工程建议是将该记录总权重1分摊到参与计算的有效地点，以免双倍计数；这仍是待在方法说明中确定的建议，不是已确认的研究结论。记录计数与地点计数分别展示。
5. **地理距离需真实定义。** `AtlasExplore.project` 是二维展示坐标，不能直接当米制／等面积坐标。确定距离、面积与平滑计算方法后再标示公里及每平方公里。KDE、网格汇总或其他方法均尚未选定。
6. **全国比较需要新索引。** 现有页面只加载当前县，不能把当前数组误当作全国。建议从现有 JSON 构建按神祇／地域分块的紧凑空间索引，包含记录、地点、来源和版本引用；选中神祇再加载。不要在首次打开时下载全国完整详情。
7. **坐标边界保持明确。** 首版只用现有 `mapped` 有效点。未来地址推算点需独立标记后才能选择纳入。视窗中心与县界外待核点保持隔离，缺失坐标不补0或县城中心。

### 最小版本的推进次序

- [ ] 先验证少量真实祭神提及的对应、分组来源筛选和去重；可从鸟取研究记录和有点位的地区选择样本，不伪造演示数据为真实神社。
- [ ] 实现可独立测试的计数／空间计算与生成索引脚本，再接入三层选择和图例。
- [ ] 扩展到全国现有点位，并显示定位缺口。此步不要求同时开展10万条记录的地理编码。
- [ ] 研究样例选择哪些神祇尚未指定；先从实际有据可查的资料中选择，不假装三位演示神祇已由用户确定。

### 验收

- [ ] 选择0／1／2／3位时交互正常，第四位不能被无提示地加入；开关一层不改变另外两层的统计尺度。
- [ ] 同一神祇的重复提及不增加权重；多神共祀记录可分别进入对应神祇层。
- [ ] 历史组、角色未区分、空祭神、未定位、多地点及疑似重复记录均有明确处理。
- [ ] 相同输入与参数得到相同统计；参数、地理单位、密度刻度和覆盖率可见。
- [ ] 三色重叠在实际底图上可辨，颜色不是唯一识别手段；图例与单层开关可使用键盘操作。
- [ ] 不能由空白图得出某地区无此信仰；图例明确这是当前资料中的奉祀分布，不代表信众人数或历史影响力的全部。
- [ ] 原有目录、详情、来源、范围筛选和离线版保持可用；新增空间索引及交互的离线支持需明确实现范围。
- [ ] 新增必要的纯逻辑测试、相关地区数据检查和浏览器核对；记录性能测量环境与结果。

## M2：定位补全与复核（未来独立阶段）

- [ ] 先统计完整现址、仅町域、旧址、氏子区域及尚未读取详情等缺口，不把 `not_published` 当作不可再定位。
- [ ] 优先补读机构详情及真正的地图标记，再对完整现址开展地址定位。
- [ ] 增加坐标方法、来源、查阅时间、精度／复核状态；原值、候选值与确认值分别保留。
- [ ] 对历史地址先核对迁址、合祀及旧行政区；不将地理编码返回的第一个点直接确认。
- [ ] 小样评估同名异社、离岛、县界、重复记录、失败重试和服务使用条件，再按地区运行；不在本轮自动触发全量网络采集。
- [ ] 坐标覆盖率分地区和神祇更新，统计可重现；若扩大可绘制状态，先同步 schema、构建、界面与测试。

## M3：三维地形（未来探索）

- [ ] 用一个已有可靠位置的地点做局部三维样例，保留二维浏览回退路径。
- [ ] 评估地形来源、许可、分辨率、下载量、离线缓存与本地 GPU／内存预算，再选择渲染引擎；本次未锁定服务或依赖。
- [ ] 统一经纬度、地形高程、单位和垂直基准；当前地点没有高程字段，缺失值不能默认为测得的海拔0米。
- [ ] 定义地点锚点与模型相对位置、朝向、尺度；检查与二维点位及地形的对齐。
- [ ] 确定热度图在三维视角中的显示方式，保持相同统计参数和来源口径。

## M4：简单 AI 神社示意模型（未来探索）

- [ ] 从一个地点开始，选择有权使用的参考照片／图纸；无充分依据时以“示意模型”呈现。
- [ ] 评估本机工具、可用资源、生成质量和许可。生成器、费用预算、云服务与批量规模均未决定。
- [ ] 保存生成工具／模型版本、输入素材来源、提示词或配置、种子（若支持）、人工修改、生成时间与许可信息。
- [ ] 先考虑通用可交付格式与压缩／LOD；GLB／glTF 是已有媒体说明中的候选，不代表查看器已实现。
- [ ] 模型与稳定 `location_id` 关联，并在界面标示“AI生成／示意／依据有限”；不将其当作实测或古建筑真实复原。
- [ ] 扩展媒体元数据／schema 前先设计版本与迁移。当前 `media_assets` 没有完整的生成过程、地理变换或高程字段。
- [ ] 设计原始素材、工作文件、可发布资产和缓存的本地目录及 Git 忽略规则；大型资源采用什么分发方式尚未决定，不先把海量二进制加入普通 Git。
- [ ] 做一次可恢复的资产导入，验证许可、校验和、地点归属、路径以及二维／三维回退行为。

## 持续维护

按功能或资料批次提交，避免将全站框架迁移、全国重新采集、热图和三维资产一次混在同一变更中。源数据及来源口径改变后同步重建统计与相应生成文件；用户提出新目标时更新本路线图的状态和优先顺序。
